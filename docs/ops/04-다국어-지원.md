# 4. 다국어 지원

## 어떤 모델인가요

유저마다 언어를 고르는 게 아니라, **서버(인스턴스) 하나에 언어 하나**예요. 셀프호스트하는 운영자가 배포 시점에 한 번 정해요. 그래서 `@nuxtjs/i18n` 같은 무거운 프레임워크(라우팅, 유저별 로케일 저장 등) 없이, 그냥 JSON 사전 하나를 골라서 문자열을 찾아주는 아주 얇은 구조예요(`app/composables/useI18n.ts`).

## 언어 정하기

`docker-compose.yml`(또는 배포 환경)에 `NUXT_PUBLIC_LOCALE`을 설정하세요. 안 주면 `ko`(한국어)예요.

```yaml
NUXT_PUBLIC_LOCALE: ja   # ko | ja | zh
```

`app/i18n/` 아래에 있는 파일 이름(`ko.json`/`ja.json`/`zh.json`)과 일치해야 해요. 없는 값을 주면 그냥 `ko`로 폴백돼요.

## 지금 어디까지 번역돼 있나요

**로그인/회원가입/비밀번호 재설정 · 마을(맵) · 게시판** 흐름은 세 언어(한국어/일본어/중국어) 다 되어 있어요. 진행 상황은 [다국어 전환 체크리스트](./05-다국어-체크리스트.md)에 화면 단위로 정리돼 있어요. 그 외 나머지 화면(개인 설정/프로필, 위키, 타임라인, 관리자 설정 등)은 전부 아직 한국어 하드코딩이에요 — `useI18n().t()`가 없는 키는 자동으로 한국어로 폴백하니 화면이 깨지진 않지만, 그 부분만 한국어로 남아있어요.

전체 앱을 한 번에 다 옮기는 대신, **기능을 새로 만들거나 손댈 때마다 그 참에 이 패턴으로 옮기는 것**을 권장해요.

## 새 화면을 i18n으로 옮기는 방법

### 1) 클라이언트 문자열

```js
const { t, errT } = useI18n()
```

`app/i18n/ko.json`(그리고 `ja.json`/`zh.json`)에 키를 추가하고, 템플릿의 하드코딩된 한국어를 `{{ t('영역.키') }}`로 바꿔요. 키는 점(`.`) 표기로 중첩할 수 있어요(예: `auth.loginTab`).

```diff
- <button>로그인</button>
+ <button>{{ t('auth.loginTab') }}</button>
```

번역이 아직 안 된 언어는 자동으로 한국어로 폴백돼요 — `ja.json`/`zh.json`에 키를 깜빡 빼먹어도 화면이 비거나 깨지지 않아요.

### 2) 서버 에러 메시지

서버 API는 지금까지 전부 `createError({ statusCode, message: '한국어 메시지' })` 식으로 한국어를 그대로 실어보냈어요. 이걸 클라이언트에서 번역할 수 있게 하려면 메시지 대신(혹은 같이) **코드**를 실어보내야 해요 — `server/utils/apiError.ts`를 씀:

```ts
import { apiError } from '../../utils/apiError'

// throw createError({ statusCode: 400, message: '이메일을 입력해주세요' })  ← 예전
throw apiError(400, 'EMAIL_REQUIRED', '이메일을 입력해주세요')  // ← 코드 추가
```

- 세 번째 인자(message)는 로그용 + `errors.EMAIL_REQUIRED` 키가 그 언어에 없을 때의 한국어 폴백이에요.
- `app/i18n/*.json`의 `errors` 영역에 같은 이름으로 키를 추가하세요.
- 클라이언트에서는 `errT(e)`로 받으면 코드가 있으면 번역, 없으면(아직 이 패턴으로 안 옮긴 오래된 엔드포인트) 서버가 보낸 한국어 메시지를 그대로 보여줘요 — 그래서 API 113개를 한 번에 다 안 바꿔도 안전해요.

```js
try {
    await $fetch(...)
} catch (e) {
    errorMsg.value = errT(e)
}
```

### 참고 예시

`server/api/auth/*.ts` + `app/pages/login.vue`/`forgot-password.vue`/`reset-password.vue`가 이 패턴을 처음부터 끝까지 적용한 예시예요 — 새 화면을 옮길 때 그대로 참고하면 돼요.

## CJK 폰트는 왜 따로 안 챙겨도 되나요

이 앱은 애초에 본문에 특정 폰트를 강제하지 않고 시스템 기본 sans-serif를 그대로 써요. 브라우저는 `<html lang="...">` 속성을 보고 같은 한자라도 그 언어권 자형(한국어/일본어/중국어)으로 알아서 그려줘요 — `app/app.vue`가 `config.public.locale` 값으로 이 속성을 런타임에 세팅해두었으니, 새 언어를 추가할 때 폰트 관련해서 따로 할 일은 없어요.
