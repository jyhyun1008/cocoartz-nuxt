# 1. 설치

## 준비물

- Docker, Docker Compose
- 서버를 외부에 공개할 도메인(HTTPS로 접근 가능해야 함) — 연합(페디버스) 기능과 로그인 세션 쿠키가 정상 동작하려면 필수예요.

## 1) 저장소 받기

```bash
git clone <이 저장소 주소>
cd cocoartz-nuxt
```

## 2) `docker-compose.yml` 값 채우기

기본으로 들어있는 `docker-compose.yml`을 그대로 쓰면 되고, `app` 서비스의 `environment:` 아래 값들을 실제 배포 환경에 맞게 바꿔주세요.

| 변수 | 설명 |
|---|---|
| `DATABASE_URL` | 기본값(`postgresql://cocoartz:cocoartz@db:5432/cocoartz`)을 그대로 써도 돼요 — `db` 컨테이너를 내부 도커 네트워크 이름으로 가리켜요. |
| `SESSION_SECRET` | **꼭 바꿔야 함.** 32자 이상 랜덤 문자열(`openssl rand -base64 32`로 생성). 안 바꾸면 컨테이너를 재시작할 때마다 전체 유저 로그인이 풀려요. |
| `NUXT_PUBLIC_API_BASE_URL` | `https://실제도메인` |
| `NUXT_DOMAIN` | 실제 도메인(프로토콜 제외). 연합(webfinger/ActivityPub)에 쓰이고, 외부에서 HTTPS로 접근 가능해야 해요. |
| `NUXT_PUBLIC_SERVER_SLUG` | 서버 식별용 slug. 아무 값이나 괜찮아요(기본 `cocoartz`). |
| `NUXT_PUBLIC_LOCALE` | 서버 언어. `ko`(기본)/`ja`/`zh` 중 하나 — 유저별이 아니라 이 서버 전체가 쓰는 언어예요. 자세한 건 [다국어 지원](./04-다국어-지원.md) 참고. |
| `NUXT_S3_*` | 선택 — 오브젝트 스토리지(S3 호환: MinIO/R2/AWS S3 등). 비워두면 아바타/아이템 이미지를 파일 업로드 없이 URL 입력으로만 쓸 수 있어요. |

> ⚠️ 이 값들은 `NUXT_` 접두사가 붙어야 실제로 반영돼요(`nuxt.config.ts`의 `runtimeConfig`를 거치는 값들이라 그럼). `DATABASE_URL`/`SESSION_SECRET`은 반대로 접두사가 **없어야** 해요(서버 코드가 `process.env`를 직접 읽음). `docker-compose.yml`에 이미 이렇게 맞춰져 있으니 이름만 그대로 두고 값만 바꾸면 돼요.

## 3) 띄우기

```bash
docker compose up -d
```

`app` 컨테이너가 시작할 때 `docker-entrypoint.sh`가 DB 마이그레이션을 자동으로 먼저 돌린 뒤 서버를 띄워요 — 따로 마이그레이션 명령을 실행할 필요 없어요.

## 4) 첫 관리자 계정 만들기

배포된 도메인으로 접속해서 **가장 먼저 회원가입하는 계정이 자동으로 관리자**가 돼요(부트스트랩). 이 시점엔 가입 방식(자유/승인제/차단)이 뭐든 상관없이 항상 가입이 통과돼요.

## 5) (권장) 가입을 열기 전에 이메일부터 설정

관리자로 로그인했다면 설정 → 이메일 탭에서 SMTP를 먼저 설정하는 걸 권장해요. 이유:

- 이메일 인증이 켜져 있어야 신규 가입자가 정상적으로 인증을 마치고 로그인할 수 있어요.
- 비밀번호 재설정(로그인 화면의 "비밀번호를 잊으셨나요?")도 이 SMTP 설정을 그대로 써요 — 안 해두면 유저가 비밀번호를 잃어버렸을 때 되찾을 방법이 없어요.
- 실제로 **이메일 설정이 끝나 있어야만 가입 방식을 "자유 가입"/"승인제 가입"으로 바꿀 수 있어요**(서버가 강제함) — 이메일 설정 전엔 "가입 차단" 상태로만 있을 수 있어요.

자세한 설정 항목은 [관리자 가이드 · 이메일 설정](../admin/04-이모지-이메일.md#이메일smtp-설정)을 참고하세요.

## 6) (선택) DB 커넥션 풀 크기 조정

`server/utils/db.ts`가 Postgres 커넥션 풀 최대 개수를 환경변수 `DB_POOL_MAX`로 읽어요(기본값 20, `docker-compose.yml`에 안 넣어도 동작). 동접이 늘면서 채팅 저장/조회가 느려진다 싶으면 이 값을 올려보되, 대개 CPU/메모리가 먼저 병목이 되니 무작정 올리기보단 실측하면서 맞추는 걸 권장해요.
