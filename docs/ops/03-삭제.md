# 3. 삭제 (서버 자체 종료)

이 서버를 **영구히** 내릴 때(예: 테스트 서버를 접고 정식 도메인으로 새로 올릴 때) 쓰는 절차예요. 되돌릴 수 없어요.

## 왜 그냥 컨테이너만 내리면 안 되나요

이 서버가 다른 페디버스 서버(마스토돈/미스키 등)와 연합돼 있었다면, 저쪽 서버들은 이 서버의 유저들을 팔로워/팔로잉 목록이나 캐시에 그대로 들고 있어요. 아무 알림 없이 그냥 내려버리면 상대 서버 입장에선 "죽었는지 살았는지 모르는 유령 계정"으로 영영 남아요. 그래서 내리기 전에 **"이 계정들은 이제 없다"는 `Delete` 활동을 연합 전체에 방송**해줘야, 상대 서버들이 자기 쪽 캐시를 정리해요(마스토돈의 `tootctl self-destruct`와 같은 목적).

## 실행

```bash
npm run db:self-destruct
```

- `.env`(또는 실행 환경)의 `DATABASE_URL`/`DOMAIN`이 **지금 내리려는 그 서버**를 가리키고 있는지 먼저 확인하세요.
- 도메인을 정확히 입력해서 **두 번 확인**받아요(오조작 방지).
- 로컬에 액터(연합 키 페어)가 있는 유저 전원에 대해, 그 유저의 팔로워 + 팔로우하던 상대에게 계정 `Delete`를 보내요.
- **로컬 DB는 전혀 안 건드려요.** 이 스크립트가 하는 일은 오직 "연합에 삭제를 알리는 것"뿐이에요 — 마스토돈의 self-destruct와 동일한 설계(로컬 데이터를 지우는 건 DB를 통째로 지우거나 볼륨을 지우는 게 어차피 더 빠르니까).

## 그 다음

연합에 알리는 게 끝났으면, 로컬 데이터는 원하는 방식대로 정리하세요.

```bash
docker compose down -v   # -v 까지 줘야 DB 볼륨(pgdata)까지 같이 지워짐
```

또는 VPS/서버 자체를 통째로 폐기해도 돼요.

## ⚠️ 이 도메인을 새 서버에 재사용하지 마세요

`self-destruct`를 돌려도 상대 서버들이 실제로 캐시를 정리한다는 보장은 없어요(요청만 보낼 뿐 강제할 순 없음). 나중에 같은 도메인으로 완전히 다른 서버(같은 소프트웨어든 다른 ActivityPub 구현체든)를 새로 띄우면, 예전 캐시와 뒤섞여 연합이 꼬일 수 있어요. 정식 서비스로 옮길 땐 **새 도메인**을 쓰는 걸 권장해요.
